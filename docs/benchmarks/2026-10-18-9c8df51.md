# First-slice direct-ASGI baseline at `9c8df51`

Measured on 2026-10-18 from FastAPI-RS commit
`9c8df51de98ff3668da8670808262cc1518694b7` with Starlette-RS
`4139a72449bf5751e8902fb1c7175ee7f191d338`. The correctness gate compared
FastAPI 0.141.1 and Starlette 1.6.0 against FastAPI-RS and passed all 13
selected first-slice cases before timing.

## Workload and environment

The workload is `fastapi.first-slice.valid-asgi`, case
`fastapi.first-slice.create-item-valid`, from
`benchmarks/workloads/first-slice-valid-asgi.yaml`. Its generated input is
`tests/fixtures/inputs/parity/first-asgi-request.json`, SHA-256
`f937e7552eb473629234576db598707748fe0a6570e5b3982022af21d4d86fbe`. The
workload declaration SHA-256 is
`fcc07446d1bc4e60a9375319a048736690647625ce6fb905de6621d11901177a`.

Per-request latency times only `await app(scope, receive, send)`. It includes
FastAPI request validation or FastAPI-RS native behavior, the Python facade,
PyO3 dispatch, response serialization, and captured ASGI sends. It excludes
application construction, interpreter startup, ASGI scope and callback setup,
HTTP client, server, and network. The separate request-loop throughput measure
also includes setup, response observation, correctness checks, and loop
bookkeeping. The Starlette control is contextual and is not subtracted from
FastAPI measurements. The full boundary is defined in
[`PARITY_BENCHMARK_PLAN.md`](../PARITY_BENCHMARK_PLAN.md#first-executable-lane).

The run used CPython 3.12.13 on macOS 15.7.7 arm64. The harness reported 12
logical CPUs but did not record a specific processor model. Rust/Cargo 1.98.1,
the Cargo release profile, and `pyo3/extension-module` were used. FastAPI source
was `95f8322ee1dcda7ceace7b1c4f6c9915b36d748f`; Starlette source was
`4f250d6b814587e20c5365f0a5f0c4d42bcb929f`. The target used Starlette-RS
`4139a72449bf5751e8902fb1c7175ee7f191d338`. Each subject had 50 warmups and
1,000 measured samples over five rounds at concurrency one. The oracle and
target shared Pydantic 2.13.4, pydantic-core 2.46.4, and AnyIO 4.12.1.

## Results

Latency is in microseconds. Ratios divide FastAPI-RS by FastAPI.

| Subject | Median | p95 | Mean | Request-loop throughput |
| --- | ---: | ---: | ---: | ---: |
| FastAPI 0.141.1 | 138.979 | 167.209 | 144.976 | 6,712.95 requests/s |
| FastAPI-RS | 172.020 | 330.917 | 202.897 | 4,839.11 requests/s |
| Starlette 1.6.0 control | 5.208 | 5.334 | 5.518 | 136,919.10 requests/s |

FastAPI-RS measured 1.238x FastAPI median latency and 1.979x p95 latency for
this request. Its request-loop throughput was lower. This is one workload on
one machine, with no performance budget applied; it is a revision-specific
baseline and shows optimization work remains.
