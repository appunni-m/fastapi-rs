## Result

observations. In this direct-ASGI workload, FastAPI-RS was slower than FastAPI:

## Measurement boundary and limits

The workload is `fastapi.first-slice.valid-asgi`. Per-request latency measures
only `await app(scope, receive, send)`. It includes the FastAPI-RS public Python
facade, PyO3 conversion, Rust implementation, Pydantic work, and Starlette-RS
dispatch. It excludes process startup, app and route construction, ASGI scope
and callback creation, observation, loop bookkeeping, server work, and network
or HTTP-client overhead. Sequential loop throughput includes per-call setup,
response observation, correctness checks, and loop bookkeeping.

Each subject used 50 warmups and five rounds of 200 sequential samples. The
gate immediately before timing passed all 15 cases. Untimed status, headers,
and body matched. The oracle ran with the default no-op OpenTelemetry providers:
it had `opentelemetry-api` but no SDK or exporter. FastAPI-RS has no telemetry
runtime implementation. The gate observes HTTP/ASGI and selected OpenAPI
outputs, not telemetry signals or lifecycle, so this result does not establish
equivalence when telemetry providers are active.
