# Direct ASGI measurements at 064c74f

Measured on 2026-10-05 at FastAPI-RS commit
`064c74f96c7e47535a954624eaea6aac4b86c974`. All seven declared workloads
passed fresh full-workflow parity gates and untimed response checks. These
selected workloads do not establish complete API compatibility.

## Environment and boundary

macOS 15.7.7, arm64; CPython 3.12.13; Rust 1.98.1; Cargo release profile with
`pyo3/extension-module`. The normal release extension was rebuilt after coverage
collection, without fault injection or coverage instrumentation. Pinned
FastAPI 0.141.1, Starlette 1.6.0, Starlette-RS `b4c8a65`, Pydantic 2.13.4 and
pydantic-core 2.46.4 identities matched the live parity receipts.

Each subject used 50 warmups and five rounds of 200 sequential samples.
Latency times `await app(scope, receive, send)`, including dispatch, validation,
and serialization. Construction, per-call setup, client/server and network
costs are excluded. Wider request-loop throughput and raw samples are saved.
The Starlette control is contextual; its costs are never subtracted.

## Observations

Latency is in microseconds. Ratios are FastAPI-RS divided by FastAPI; values
below 1 indicate lower target latency in this run.

| Workload | FastAPI median | FastAPI-RS median | Median ratio | p95 ratio |
| --- | ---: | ---: | ---: | ---: |
| Nested dependencies, distinct query aliases | 498.12 | 383.65 | 0.770 | 0.810 |
| Nested dependencies, two query fields | 421.25 | 333.92 | 0.793 | 0.808 |
| First slice, chunked body | 138.67 | 50.29 | 0.363 | 0.351 |
| First slice, invalid request | 148.00 | 231.92 | 1.567 | 1.222 |
| First slice, valid request | 334.79 | 72.06 | 0.215 | 0.729 |
| Response model, 300 nested records | 369.06 | 712.23 | 1.930 | 1.887 |
| Repeated sequence query | 102.46 | 32.79 | 0.320 | 0.344 |

Five workloads measured faster; invalid requests and large response models
remain slower. This sequential single-machine run does not establish network
throughput, concurrent performance, cross-revision improvement, or later-build
performance. The valid-request median and p95 ratios differ substantially;
raw samples must be retained when interpreting that distribution.

Later source review found worker scheduling gaps in this revision. The three
first-slice workloads omitted the source's worker dispatch for `current_actor`;
the repeated-sequence workload ran its synchronous endpoint inline; the large
response workload omitted both endpoint and response-validation worker calls.
Those five rows are diagnostic output comparisons, and cannot establish
equivalent execution costs until callback/thread parity is implemented and
observed. The two nested-dependency workloads execute asynchronous endpoints
and override trees. The gates select public HTTP/ASGI outcomes and do not
establish complete callback/thread parity. The later lazy dependency scheduler
addresses dependency worker dispatch; these historical timings were not rerun
against that change.
