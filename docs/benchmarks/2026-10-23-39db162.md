# FastAPI-RS first-slice benchmark at FastAPI 0.157.0

## Result

The fresh identity-checked gate passed all 15 selected observations. FastAPI-RS
was slower than FastAPI in this direct-ASGI measurement: median latency was
1.216x and p95 latency was 1.531x the oracle. This is one workload on one host;
it does not establish broad performance or parity.

| Subject | Median | p95 | Samples |
| --- | ---: | ---: | ---: |
| FastAPI 0.157.0 | 132.916 µs | 172.708 µs | 1,000 |
| FastAPI-RS | 161.666 µs | 264.334 µs | 1,000 |
| Starlette control | 5.250 µs | 5.375 µs | 1,000 |

The Starlette control is contextual and does not implement FastAPI validation
or dependency behavior; its time is not subtracted from either FastAPI result.

## Measurement boundary

The workload is `fastapi.first-slice.valid-asgi`, using the reviewed input
`tests/fixtures/inputs/parity/first-asgi-request.json`. Its declaration is
`benchmarks/workloads/first-slice-valid-asgi.yaml`. The timer covers only
`await app(scope, receive, send)`: it includes the target facade, PyO3
conversion, Rust implementation, Pydantic work, and Starlette-RS dispatch.
It excludes process startup, application and route construction, ASGI scope
and callback construction, observation, event-loop bookkeeping, server work,
and network/client overhead.

Each subject used 50 warmups and five rounds of 200 sequential samples. Raw
latency samples are retained in the ignored result artifact. The 15-case parity
gate completed immediately before timing and compares the declared observation
selectors across the pinned oracle and target.
