# FastAPI-RS first-slice ASGI benchmark at `f4600d2`

## Result

The 14-case first-slice parity gate passed **14/14 selected observations**
before timing. On this single host, FastAPI-RS had 1.164× the FastAPI median
latency and 1.309× the p95 latency. This is one direct-ASGI scenario, not a
network measurement, a full-suite result, or a general performance conclusion.

| Subject | Median latency | p95 latency | Request-loop throughput |
|---|---:|---:|---:|
| FastAPI 0.141.1 | 134.7 µs | 155.5 µs | 7,070 requests/s |
| FastAPI-RS | 156.8 µs | 203.5 µs | 5,796 requests/s |
| Starlette 1.6.0 control | 4.96 µs | 6.33 µs | 148,043 requests/s |

Ratios are FastAPI-RS divided by FastAPI. The Starlette control is contextual
and is not subtracted from either FastAPI measurement. Request-loop throughput
also includes per-call setup, response observation, correctness checks, and
loop bookkeeping; it is separate from per-request latency.

## Measurement boundary

Per-request latency times only `await app(scope, receive, send)`. It includes
FastAPI request validation on the oracle and native FastAPI-RS behavior on the
target, the target Python facade and PyO3 conversion, ASGI dispatch, response
creation, and captured sends. It excludes interpreter startup, app and route
setup, scope and callback construction, response observation and correctness
checks, loop bookkeeping, HTTP server work, and network or client overhead.
The three subjects ran sequentially at concurrency 1 with 50 warmups and five
rounds of 200 samples; all 1,000 latency samples per subject were retained.
