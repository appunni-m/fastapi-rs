# FastAPI-RS first-slice benchmark at FastAPI 0.157.0

## Result

The current identity-checked gate passed all 15 selected observations. FastAPI-RS
was slower than FastAPI in this direct-ASGI measurement: median latency was
1.218x and p95 latency was 2.223x the oracle. This is one workload on one host;
it does not establish broad performance or parity.

| Subject | Median | p95 | Samples | Sequential loop throughput |
| --- | ---: | ---: | ---: | ---: |
| FastAPI 0.157.0 | 131.812 µs | 156.458 µs | 1,000 | 7,180 req/s |
| FastAPI-RS | 160.521 µs | 347.875 µs | 1,000 | 5,167 req/s |
| Starlette control | 5.083 µs | 5.417 µs | 1,000 | 147,845 req/s |

The Starlette control is contextual and does not implement FastAPI validation
or dependency behavior; its time is not subtracted from either FastAPI result.

## Measurement boundary

The workload is `fastapi.first-slice.valid-asgi`. Per-request latency measures
only `await app(scope, receive, send)`: it includes the target facade, PyO3
conversion, Rust implementation, Pydantic work, and Starlette-RS dispatch. It
excludes process startup, application and route construction, ASGI scope and
callback construction, observation, loop bookkeeping, server work, and network
or HTTP-client overhead. Sequential loop throughput includes per-call setup,
response observation, correctness checks, and loop bookkeeping.

Each subject used 50 warmups and five rounds of 200 sequential samples. The
benchmark gate immediately before timing compared all 15 selected observations
and passed 15/15. Untimed status, headers, and body matched across all three
subjects. Raw latency samples are retained in the ignored benchmark receipt.
