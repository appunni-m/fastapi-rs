## How to read this inventory

- `surfaces` is the recursive lock closure from the default runtime, each FastAPI extra, and each dependency group. Group closures follow nested `include-group` entries in the pinned `pyproject.toml`; `group:dev` includes `tests`, `docs`, `translations`, and its own tools. Group surfaces show group dependency closure without repeating FastAPI's base runtime closure.
- `incoming edges` lists each lock edge that reaches a package. `parent[extra] -> child` means the parent extra activates that edge; `[extra=name]` records extras requested on the child; `[marker=...]` preserves that exact edge's lock marker. Root edges name `fastapi (root)`, `fastapi[feature] (root)`, `fastapi[feature] (base root)`, or `group:name (root)` before `-> child`. The graph unions all lock markers and does not evaluate them for one machine or Python version.
- `make dependency-graph-update` rewrites lock-derived surfaces, incoming edges, representative consumer paths, source-use status, and profile counts. `make dependency-graph-check` verifies those fields against the pinned lock and the reviewed source-use file while preserving the package-summary, implementation/language, license, and FastAPI-import annotations.
- `FastAPI imports` is a static scan of upstream Python modules shipped under `fastapi/`, mapped to locked distribution names. `yes` means direct source import; `no` means no direct import found. It describes the oracle package only and does not imply a FastAPI-RS target dependency. It does not claim that transitive runtime libraries are unused by Starlette/Pydantic.
- PyPI summaries are package-description context, not evidence of why FastAPI selected a dependency. The final column records a source-backed purpose using the pinned FastAPI/Starlette source or exact-version dependency source along the lock path. If evidence shows only an optional package capability, the purpose says that FastAPI does not demonstrate invoking it; the record does not imply FastAPI behavior. Unmapped purposes remain unresolved with a representative lock-derived path. Implementation/language labels use release classifiers and wheel metadata plus identified native implementations. License is exact release metadata or a classifier fallback; no classifier is not evidence that code is unlicensed.

## Build, runtime, and license interpretation

- The version values are the exact lock resolutions, not FastAPI’s minimum accepted dependency ranges. Consumers can resolve newer compatible versions; this inventory is the reproducible analysis baseline only.
- Optional extras (`standard`, `standard-no-fastapi-cloud-cli`, `all`) are alternative FastAPI install surfaces. `all` includes the broad CLI, HTTP client, templates, multipart, signing, YAML, email, Uvicorn standard, settings, and extra-type packages. `standard` adds `fastar`; the “no cloud CLI” extra selects the correspondingly named FastAPI CLI extra. All extras still include the five default runtime roots.
- Some development/tool dependencies are themselves implemented partly in Rust or ship native extensions (for example Rust-backed linters/type tools, file watchers, Pydantic core, C/Cython-based protocol or coverage accelerators). They are not therefore FastAPI runtime requirements unless reached from the default runtime closure.
- License fields use exact PyPI SPDX/license metadata first and classifier fallback when absent. PyPI omitted declarations for `caio` and `mypy-extensions`; the pinned source distributions’ `COPYING` and `LICENSE` files identify Apache-2.0 and MIT respectively. BSD/LGPL classifier-only entries preserve the stated family and flag missing variant detail; do not infer a specific exception or use right from that label. Preserve upstream notices.
- This graph is a dependency-purpose inventory, not an import-usage proof for every transitive edge. Direct-import detection is static and cannot observe `importlib`, plugins, entry points, or code paths in dependencies.
