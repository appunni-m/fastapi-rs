# FastAPI 0.141.1 dependency graph

> Source: the official FastAPI checkout at tag `0.141.1` (commit `95f8322ee1dcda7ceace7b1c4f6c9915b36d748f`), its `pyproject.toml` and `uv.lock` (`version = 1`, `revision = 3`), plus exact-version PyPI release metadata. FastAPI is Python >=3.10. The lock contains 204 third-party distributions and one editable local FastAPI root; this is a locked development universe, not an installed runtime set. That FastAPI root is source-oracle provenance only and must never be installed or imported by the FastAPI-RS target.

FastAPI-RS may separately declare Pydantic and Starlette-RS as pinned runtime
components; the oracle graph does not carry over all upstream packages. Python
runtime modules contain only direct native re-exports and literal `__all__`,
with no functions, branches, loops, or fallback behavior. FastAPI-specific
routing, dependency resolution, validation orchestration, serialization/OpenAPI,
middleware, lifecycle, and protocol control flow belongs in Rust.

The graph faithfully reports FastAPI's source-lock dependency versions for
dependency analysis. Compatibility and parity use Starlette 1.6.0 at
`4f250d6b814587e20c5365f0a5f0c4d42bcb929f` as the sole compatibility profile;
FastAPI declares `starlette>=0.46.0`.

## How to read this inventory

- `surfaces` lists where a package is reachable: default runtime, FastAPI extras, and dependency groups (groups include nested `include-group` entries as declared in `pyproject.toml`). The group `dev` is composite: it includes `tests`, `docs`, and `translations`, plus its own tools.
- `incoming edges` lists every locked package parent edge observed in any surface. `parent[extra] -> package` means that edge is activated by the parent extra; `; marker` is the lock marker. `fastapi[...] (root)` and `group:... (root)` are direct project roots. This records marker strings without pretending one machine realizes every platform.
- `FastAPI imports` is a static scan of upstream Python modules shipped under `fastapi/`, mapped to locked distribution names. `yes` means direct source import; `no` means no direct import found. It describes the oracle package only and does not imply a FastAPI-RS target dependency. It does not claim that transitive runtime libraries are unused by Starlette/Pydantic.
- Purpose uses exact-release PyPI summaries as concise context; language/component labels use release classifiers and wheel metadata, plus named native implementations where the component is explicit. `Not stated` flags incomplete upstream metadata. License is the exact release metadata when stated or its license classifier fallback; no classifier is not evidence that code is unlicensed.

Every `extra:*` reachability count includes this default runtime closure.
- The `[build-system]` declares `pdm-backend` as its build backend, but `pdm-backend` is **not in `uv.lock`**. Treat it as a separate build requirement (PyPI project: PDM backend, Python implementation, MIT; verify the exact resolved build version before packaging).
- Platform/Python conditional examples retained in the edge table include AnyIO’s `exceptiongroup` (<3.11) and typing-extensions (<3.13), Starlette’s typing-extensions (<3.13), Uvicorn colorama (Windows), and Uvicorn uvloop (not PyPy/Cygwin/Windows). `uv.lock` carries wheel alternatives per distribution and lock resolution markers; those wheel files are platform build variants, not separate package versions.
- The lock has one version/source record per normalized distribution name (no duplicate package-version rows). Platform choice is represented by markers and alternative wheel artifacts. ABI/platform-specific wheels occur for packages including `argon2-cffi-bindings`, `caio`, `cffi`, `coverage`, `cryptography`, `greenlet`, `httptools`, `jiter`, `markupsafe`, `pillow`, `psutil`, `pyyaml`, `regex`, `uvloop`, `watchdog`, `watchfiles`, `websockets`, plus native Rust tools and bindings. Wheels span macOS, Windows, manylinux/musllinux, CPython ABI/abi3 and, for some projects, PyPy/free-threaded Python. The lock keeps hashes for the available wheel files.

## Build, runtime, and license interpretation

- The version values are the exact lock resolutions, not FastAPI’s minimum accepted dependency ranges. Consumers can resolve newer compatible versions; this inventory is the reproducible analysis baseline only.
- Optional extras (`standard`, `standard-no-fastapi-cloud-cli`, `all`) are alternative FastAPI install surfaces. `all` includes the broad CLI, HTTP client, templates, multipart, signing, YAML, email, Uvicorn standard, settings, and extra-type packages. `standard` adds `fastar`; the “no cloud CLI” extra selects the correspondingly named FastAPI CLI extra. All extras still include the five default runtime roots.
- Some development/tool dependencies are themselves implemented partly in Rust or ship native extensions (for example Rust-backed linters/type tools, file watchers, Pydantic core, C/Cython-based protocol or coverage accelerators). They are not therefore FastAPI runtime requirements unless reached from the default runtime closure.
- License fields use exact PyPI SPDX/license metadata first and classifier fallback when absent. PyPI omitted declarations for `caio` and `mypy-extensions`; the pinned source distributions’ `COPYING` and `LICENSE` files identify Apache-2.0 and MIT respectively. BSD/LGPL classifier-only entries preserve the stated family and flag missing variant detail; do not infer a specific exception or use right from that label. Preserve upstream notices.
- This graph is a dependency-purpose inventory, not an import-usage proof for every transitive edge. Direct-import detection is static and cannot observe `importlib`, plugins, entry points, or code paths in dependencies.
