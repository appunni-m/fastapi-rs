## Contract ownership

**FastAPI owns the adapter and validation contract.** In `../fastapi/fastapi/datastructures.py:21-64`, `UploadFile` subclasses Starlette's class and declares FastAPI-facing fields and documentation. Its async `write`, `read`, `seek`, and `close` methods only await the corresponding superclass methods (`:66-130`). FastAPI's Pydantic validator accepts any Starlette `UploadFile`, returns that same object, and raises `ValueError("Expected UploadFile, received: …")` for other values; its JSON schema is `string` with `application/octet-stream` (`:132-150`). FastAPI also classifies UploadFile annotations as `File` parameters (`../fastapi/fastapi/dependencies/utils.py:498-501`).

**Starlette owns the file and operation semantics.** Its constructor stores the supplied `file`, `filename`, and `size`, selects `headers or Headers()`, and caches the file's `_max_size` (`../starlette/starlette/datastructures.py:415-430`). It does not derive `size` from the file. `content_type` is `headers.get("content-type", None)` (`:432-435`). `_in_memory` treats absent `_rolled` as rolled; `_will_roll` is true for an already-rolled file or when `tell() + len(data)` is strictly greater than a truthy max size, with zero meaning unlimited (`:437-449`). `write` increments non-`None` size before checking rollover or writing, so that increment is observable even if the later rollover check or file write raises (`:451-459`). `read`, `seek`, and `close` call the file directly while in memory, and use `run_in_threadpool` after rollover (`:461-476`). File-method exceptions are not translated by `UploadFile`; they propagate from the awaited operation.

Multipart-created uploads use `SpooledTemporaryFile(max_size=1 MiB)`, start with `size=0`, and retain part headers (`../starlette/starlette/formparsers.py:146-175, 225-237`). The parser writes file chunks through `UploadFile.write`, seeks each finished upload to offset zero, and closes open temporary files if parsing fails (`:271-297`). Request cleanup closes parsed form uploads through `FormData.close` (`../starlette/starlette/requests.py:313-326` and `../starlette/starlette/datastructures.py:482-497`). These are Starlette contracts, not FastAPI-specific I/O behavior.

## FastAPI-RS target path

The public Python facade directly re-exports `fastapi_rs._core.UploadFile` (`fastapi-rs-py/python/fastapi/datastructures.py:19-23`). FastAPI-RS registers a runtime-created subclass of the active Starlette-RS `UploadFile`, installs FastAPI's annotations, method docs/signatures, and Pydantic hooks, and copies the Starlette method bodies for its four overrides (`fastapi-rs/src/datastructures.rs:98-203, 369-429, 430-529`). This matches FastAPI's split: FastAPI owns the subclass-facing shape and validation; Starlette-RS owns the generic file behavior.

The base target constructor keeps the Python file object, metadata, headers, and cached `_max_size`, with a falsey-header fallback matching Starlette (`/private/tmp/fastapi-rs-starlette-rs-4139a724/starlette-rs-py/src/datastructure_runtime.rs:994-1027`). Its getters/setters and `content_type` lookup are at `:1030-1108`. The in-memory and rollover checks mirror Starlette's `_rolled` default, `tell() + size_to_add` comparison, and zero-threshold handling (`:1228-1251`). The operation state machine increments size before the write, calls the same file method, uses `starlette.concurrency.run_in_threadpool` for rolled files, and forwards awaited errors (`:1305-1369`). The Python base methods call those native entry points (`/private/tmp/fastapi-rs-starlette-rs-4139a724/starlette-rs-py/python/starlette/datastructures.py:280-315`).

Multipart parsing on the target likewise creates a Python `SpooledTemporaryFile` with a 1 MiB threshold and wraps it as Starlette-RS `UploadFile(size=0, filename=…, headers=…)` (`/private/tmp/fastapi-rs-starlette-rs-4139a724/starlette-rs-py/src/request_runtime.rs:2089-2126`). It writes chunks and seeks finished files to zero through the public async methods (`:1904-1937, 1952-1970`); request cleanup closes the form object (`/private/tmp/fastapi-rs-starlette-rs-4139a724/starlette-rs-py/python/starlette/requests.py:169-185`, `/private/tmp/fastapi-rs-starlette-rs-4139a724/starlette-rs-py/src/datastructure_runtime.rs:758-832`).

The inspected ordinary sequential path has no source-level difference found for metadata access, size accounting, in-memory/rolled dispatch, or file-method error propagation. The native target also contains an internal `RuntimeError("UploadFile is already borrowed")` branch (`/private/tmp/fastapi-rs-starlette-rs-4139a724/starlette-rs-py/src/datastructure_runtime.rs:960-976`) with no Starlette counterpart; no current FastAPI parity case exercises it, and this audit did not attempt runtime reachability analysis.
