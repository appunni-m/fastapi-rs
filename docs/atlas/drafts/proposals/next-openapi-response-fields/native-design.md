## Small proposed integration

1. **Snapshot the primary owner.** Add `primary_field: Option<ResponseField>` to OpenApiRouteSnapshot, cloning `route.response_field.field(py)?` alongside extras after existing included-field materialization. Keep raw model metadata where other existing paths require it, but generate primary JSON from the retained adapter whenever that owner exists. Clone Rust/Py references under a short app borrow; read attributes, generate, normalize, and destroy temporaries after release. Do not construct another ResponseField or TypeAdapter during this response batch.
2. **Collect once before operation assembly.** Introduce a document-local ordered collection of primary then populated extra owners for each schema-eligible route snapshot. Assign an internal ordinal key to every distinct field; use `(key, field.mode)` for lookup. Rust indices or private integer tokens are sufficient, never user annotation/class names, operation IDs, status alone, exposed addresses or fixture IDs. Hold owner references until generation and assembly finish. Selected modes are all serialization.
3. **One native-orchestrated Pydantic batch.** Create the existing native `_FastApiGenerateJsonSchema` subclass once with the source ref template, collect `(key, mode, retained_adapter.core_schema)` into a PyList in that order, and call `generate_definitions` once. Rust owns collection/order/control flow; Pydantic remains the pinned schema dependency. Retain the returned field mapping and definitions separately. Apply the source form-feed description truncation to returned definitions, rather than regenerating them. No error-triggered raw-annotation fallback or broad exception bypass: propagate the actual generator/hook error, preserving earlier user journal/warning effects.
4. **Lookup from field ownership.** Primary and extra assembly consume their keyed mapping entries. Reuse the source-aligned outer-title helper against those entries: skip `$ref`; choose truthy outer title, otherwise truthy serialization alias, otherwise alias if not None, otherwise field name; use Python `.title().replace('_', ' ')`. Mutate the mapped schema as source does, without rebuilding schema or synthesizing a primary name from endpoint/path. A missing mapping is an error, never an empty-schema fallback. For batched entries preserve the exact generated reference; avoid extracting a model name and reconstructing `$ref`, which can lose escaping/remapping. Internal schema provenance can distinguish already-mapped field schemas from existing standalone request/body schemas so assembly does not overwrite mapped titles again.
5. **Definitions belong to the document.** Pass the batch definitions directly to openapi.rs document assembly, not `$defs` embedded independently in every response field. Merge the existing operation-generated validation definitions afterward and sort final component names as source does. Keep legacy request/body/stream generation explicitly separate until those owners/modes/flattening receive their own gate; do not claim this response-only batch is FastAPI's complete all-fields batch. Generic collection of available response owners must not branch on primitive fixture names or special-case the shared ref.
6. **Publish only a complete document.** Keep mapping/definitions/generator local to a cache miss. A JSON-hook failure leaves retained route fields and prior app cache/version untouched; the next public call constructs a fresh generator and retries the whole document. Publish only after operation assembly and final encoding succeed. Cache hits return the same retained public document without any generator/hook work. Keep cache truthiness, callbacks and retired-reference destruction outside app borrows/cache locks. Do not retain/reuse the one-shot generator or add a generation-in-progress mutex across user hooks. Current explicit `openapi_schema` setter and general reentry/concurrency remain separate prior gaps.

This is a structural response-field improvement, not a claim that the unselected response/model modes are fully supported. It preserves route-time ownership and worker validation/serialization scheduling. Any missing ownership or unsupported branch must remain visible; never retry a failed batch through the old helper after its callbacks already ran.

## Exact wire ordering is a separate assembly obligation

Source get_openapi builds paths/responses, sorts component names (utils.py668–669), then validates through `OpenAPI(**output)` and `jsonable_encoder(..., by_alias=True, exclude_none=True)` at679. That last model stage controls many wire key orders and coercions; raw builder insertion order or globally sorted JSON is not equivalent. Current openapi.rs uses native ordered dictionaries plus schema_key_rank907 to reconstruct Schema declared-field order, with stable extension-key order; it does not instantiate the source's complete OpenAPI models. Keep that limitation explicit.

For the selected ordinary shape, preserve top-level OpenAPI/info/paths then optional components order; info title/version; operation summary/operationId/responses; primary status then extra status insertion order, including 409 before202; Response description before content; MediaType schema; Schema declared known fields before ordered extensions. Components use sorted names; Pydantic's own definition sorting590–619 preserves property/default order. Preserve extension values, the actual generated refs, and schema descriptions. Do not recursively alphabetize paths/statuses or blanket-sort extension dictionaries. Existing schema normalization remains native production assembly behavior, not permission to normalize fixture comparisons; broad final-model validation/coercion is unselected.

The primary title must derive from the retained `Response_<unique_id>` field name, including an explicit operation ID. Docs dispatch10424–10434 serializes the returned cached document through ordinary compact JSON; `/document` returns the same public result via JSONResponse. Keep content length, ordered headers, exact bytes, error sends and more_body presence. A parsed-document match does not discharge those raw selectors.
