## Verified source surface

`fastapi.exceptions` has no `__all__`. Its source-defined declarations and imported names are therefore both discoverable at the module path, but importability alone is not a consumer contract. `fastapi.exception_handlers` defines three async functions and also binds helper and Starlette names in its module namespace. The pinned source inventory records these members; the compatibility decision must come from reviewed docs and policy.

The other module bindings in `fastapi.exceptions` (`Mapping`, `Sequence`, `Annotated`, `Any`, `TypedDict`, `Doc`, Pydantic `BaseModel`/`create_model`, and the two `Starlette*Exception` aliases) are implementation imports. The bindings in `fastapi.exception_handlers` (`Request`, `HTTPException`, `Response`, `JSONResponse`, `WebSocket`, the encoder/helper imports, and the close-code constant) likewise support the functions. Existing import-binding reviews classify these paths private/internal. The docs instruct users to import Starlette's HTTP exception from `starlette.exceptions`, not the incidental `fastapi.exceptions.StarletteHTTPException` alias.

FastAPI owns these exception classes, validation aggregation/context, default handler functions, handler registration, and handler selection supplied by its application setup. The HTTP/WebSocket exception base classes, generic handler dispatch, response objects, ASGI send/close behavior, and server-error middleware belong to Starlette 1.6.0. In Starlette, exception handlers are found through the exception MRO and are invoked only before response start (`starlette/_exception_handler.py:16-63`). Pydantic supplies validation record types/shapes; FastAPI aggregates and encodes those records.

## Exact fixture and manifest gaps

1. The pinned FastAPI source makes `fastapi.HTTPException` identical by direct re-export to `fastapi.exceptions.HTTPException`, and likewise for `WebSocketException`. The current root-alias identity recipe covers Starlette re-exports, not these FastAPI exception classes. A source binding is not an identity-checked parity result.
2. The two documented default functions have reviewed metadata overlays but remain operation-scope pending/full-contract-not-established. Current input cases mostly exercise them through registered ASGI behavior. No recipe directly probes their required argument names/annotations/return values, module object identity, and direct-call result matrix. These gaps do not erase the docs-backed consumer contract.
3. `websocket_request_validation_exception_handler` is visible in the source inventory and installed by FastAPI, but has no operation overlay; existing source classification is private/internal. The default-close recipe samples the registered path but does not probe direct import/signature. **Proposal:** retain private/internal classification unless the public contract is deliberately expanded; keep the exception type itself independently classified and mapped.
4. `HTTPException` and `WebSocketException` have root-only signature probes and selected ASGI outputs. There is no direct constructor case checking both root/module identity, `.args`, all exposed fields, defaults, and base-class relationship. The HTTP sample covers structured detail, an added header, a Starlette base exception, and a bodyless status; the WebSocket sample covers close code/reason. These samples are not complete exception-class contracts.
5. Request error object mapping is partial: the direct workload checks `RequestValidationError`, but there is no corresponding direct constructor/signature slice for `WebSocketRequestValidationError`, `ResponseValidationError`, or base `ValidationException`. Response/WebSocket route cases cover selected generated errors only. The base `ValidationException.errors()` operation remains scope-review-pending despite the request-error workload invoking it as part of a captured body.
6. Candidate review status needs to remain explicit for `FastAPIError`, `DependencyScopeError`, and `PydanticV1NotSupportedError` (private/internal); `FastAPIDeprecationWarning`, `RequestErrorModel`, and `WebSocketErrorModel` (uncertain); plus `EndpointContext` and its fields (private/internal). The error-model values have no pinned-source consumer. Do not infer public support from inventory visibility.
7. Metadata's generic `http-exception` selector rule includes `fastapi.exceptions.StarletteHTTPException` as a candidate path, while the import-binding review classifies that alias as private/internal and the docs prescribe the canonical `starlette.exceptions.HTTPException` path. **Proposal:** confirm that selector alias is only an oracle/target selector and does not imply a public FastAPI import contract.
