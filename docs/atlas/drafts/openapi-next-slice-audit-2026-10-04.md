## Pinned source signatures, aliases, and deprecations

- `get_openapi` is keyword-only: `(*, title: str, version: str, openapi_version: str = "3.1.0", summary: str | None = None, description: str | None = None, routes: Sequence[BaseRoute | RouteContext], webhooks: Sequence[BaseRoute | RouteContext] | None = None, tags: list[dict[str, Any]] | None = None, servers: list[dict[str, str | Any]] | None = None, terms_of_service: str | None = None, contact: dict[str, str | Any] | None = None, license_info: dict[str, str | Any] | None = None, separate_input_output_schemas: bool = True, external_docs: dict[str, Any] | None = None) -> dict[str, Any]` (`../fastapi/fastapi/openapi/utils.py:585-679`). It inserts optional metadata only when truthy, traverses both routes and webhooks, then applies `OpenAPI(**output)` and `jsonable_encoder(..., by_alias=True, exclude_none=True)`. Pydantic owns validation and model serialization in this step.
- `FastAPI.openapi(self) -> dict[str, Any]` (`../fastapi/fastapi/applications.py:1070-1103`) caches the generated mapping and refreshes it when the route version changes. The `/openapi.json` handler uses a shallow response copy to add a request root-path server (`:1105-1120`); repeated requests must not mutate the cached document.
- The reviewed constructor cohort has generated Pydantic signatures, not source-defined `__init__` methods. Use the pinned reflection in `tests/fixtures/runtime-api-surface-standard.json` for exact signatures. Source fields establish that `OpenAPI` requires `openapi` and `info`; `Info` requires `title` and `version`; `Reference` requires `ref`; `Schema` fields are optional with `None` defaults. These models except `Reference` inherit `BaseModelWithConfig` with `extra="allow"`; `Reference` directly subclasses `BaseModel`.
- Important source field aliases are Pydantic serialization/validation aliases, not import aliases: `Reference.ref -> "$ref"`; `Schema.schema_ -> "$schema"`, `vocabulary -> "$vocabulary"`, `id -> "$id"`, `anchor -> "$anchor"`, `dynamicAnchor -> "$dynamicAnchor"`, `ref -> "$ref"`, `dynamicRef -> "$dynamicRef"`, `defs -> "$defs"`, `comment -> "$comment"`, `not_ -> "not"`, `if_ -> "if"`, and `else_ -> "else"`. Nearby follow-on aliases include `PathItem.ref -> "$ref"`, `MediaType.schema_` and `ParameterBase.schema_ -> "schema"`, `Parameter.in_ -> "in"`, `SecurityBase.type_ -> "type"`, and `APIKey.in_ -> "in"`.
- `Schema.example` carries a `typing_extensions.deprecated` annotation directing callers to `examples`; it is not a warning emitted on ordinary construction. The `Schema.deprecated` field is ordinary OpenAPI data. The utility `generate_operation_id(*, route, method) -> str` is the runtime deprecation: each call emits `FastAPIDeprecationWarning` with the pinned message that it is deprecated, unused internally, and will be removed soon. Its fallback invokes deprecated `generate_operation_id_for_path`, so fallback produces the second warning as well. It is lower priority than the generator and model cohort because direct warning-capturing inputs already exist.
- The four public docs symbols also remain pending: `get_swagger_ui_html(*, openapi_url: str, title: str, swagger_js_url: str = ..., swagger_css_url: str = ..., swagger_favicon_url: str = ..., oauth2_redirect_url: str | None = None, init_oauth: dict[str, Any] | None = None, swagger_ui_parameters: dict[str, Any] | None = None) -> HTMLResponse`; `get_redoc_html(*, openapi_url: str, title: str, redoc_js_url: str = ..., redoc_favicon_url: str = ..., with_google_fonts: bool = True) -> HTMLResponse`; `get_swagger_ui_oauth2_redirect_html() -> HTMLResponse`; and the mutable literal `swagger_ui_default_parameters` (`../fastapi/fastapi/openapi/docs.py:22-37,40-194,197-298,301-389`). No source deprecation or field alias applies to these helpers.

Direct API workflow v3 currently observes signatures, strict JSON attributes/return values, call outcomes, and captured warnings. Its JSON return path uses `json.dumps` and rejects Pydantic model instances. It cannot presently return a constructed model's `model_dump(by_alias=True, exclude_none=True)` or field metadata through an existing observation. `python_call_outcome` can distinguish a raised validation error from a successful call, but a successful constructor result is only reported as `returned`. A future model-constructor workflow therefore needs either an explicit model-projection observation or a separate identity-checked harness that owns the public call and JSON projection. Do not pretend the existing signature-only recipe covers this.

- For docs, the executable binding exists in `fastapi-rs/src/docs.rs::register` and `fastapi-rs-py/python/fastapi/openapi/docs.py` directly re-exports the four names from `_core`. ## Concrete next backlog slice

First record the six-item generator/model seed above as one explicit OpenAPI contract slice, without promoting the surrounding module wholesale. The scope should specify:

1. For `get_openapi`, keep the exact keyword-only signature and add input-only bundles for one ordinary route, one webhook, `separate_input_output_schemas=False`, truthy versus falsy optional metadata, and duplicate operation IDs. Keep validation failures as `python_call_outcome` cases; its raised outcome already records error class and message, and the source does not catch the nested Pydantic errors.
2. For `FastAPI.openapi`, link the existing cache and root-path ASGI recipes to the reviewed row. The cache workflow already observes identity through response booleans around repeated `app.openapi()` calls and direct route registration; keep it explicitly mapped instead of treating it as direct callable identity. Keep constructor configuration, route-version invalidation, and request-root-path response copying as separate clauses.
3. Start model inputs with `OpenAPI`, `Info`, `Schema`, and `Reference`: cover required versus omitted fields, extra input, Python field name versus alias input, and alias serialization for `$ref`, `$schema`, `$defs`, `not`, `if`, and `else`. Include `Schema(type=...)` and the existing `multipleOf > 0` / nonnegative integer field boundaries. Use pinned Pydantic reflection for constructor signatures and errors.
4. Before adding expected-result comparisons for constructed models, add or select an isolated observation path that safely projects model instances to JSON using the pinned model's alias/exclude-none rules. The current direct API return selector rejects model objects. Recipes remain input-only and must not contain expected values.
5. After the generator/model seed, close the already implemented docs-helper direct surface as a separate four-row slice: bind `docs.rs::register`, record signatures and `swagger_ui_default_parameters`, and reuse the existing ASGI HTML cases for output. Include Swagger override/OAuth escaping, ReDoc fonts, and OAuth redirect HTML while keeping generic response semantics with Starlette.

The following model families remain later backlog: `Components` maps, operation/path-item/request/response/parameter graph, server/tag metadata, and OAuth/security variants. Existing generated-document selectors are useful inputs for those later rows, but they are not substitute constructor evidence. No tests, build, or parity commands were run.
