## Pinned FastAPI source facts

- `FastAPI` subclasses Starlette's application (`fastapi/applications.py:42`). Its constructor builds an `APIRouter` with route, dependency, lifecycle, response-class, and strict-content-type configuration, installs default exception handlers, and registers OpenAPI/docs routes (`applications.py:984-1018`, `1105-1158`). `FastAPI.__call__` writes configured `root_path` into the scope and delegates to Starlette (`applications.py:1160-1163`).
- `FastAPI.add_api_route` forwards route options to its router (`applications.py:1165-1220`). `api_route` forwards its options through the route decorator (`1301-1359`); the verb decorators are convenience registrations, e.g. `get` and `post` (`1646+`, `2397+`). The selected first-slice workload uses only `app.post`, with `status_code=201` and a response model.
- `APIRouter` extends Starlette `Router` (`fastapi/routing.py:2255`). Its `add_api_route` selects route class, joins prefix, inherits response class/tags/dependencies/callbacks/responses and schema policy, constructs the route, then appends it (`2889-2971`). `include_router` validates cycles/prefixes, composes include context, stores the included router, and merges lifecycle handlers (`3133-3319`).
- `APIRoute` builds its dependency/body plan and resolves an explicit or inferred response model (`routing.py:961-1123`); `get_route_handler` passes route state into the handler (`1126-1245`). The handler reads chunked request bytes through `Request.body()`, chooses JSON parsing from body-field and Content-Type policy, converts JSON decode failures to request-validation errors, solves dependencies, and raises aggregated request errors (`375-489`, `751-759`).
- A non-`Response` endpoint value is response-model validated and serialized; a returned Starlette `Response` bypasses that path. Response-class construction, status/body suppression, and dependency response headers have separate branches (`routing.py:301-342`, `706-759`). The direct-`Response` path is at `711-715`.

Each HTTP action observes status, headers, full body, and ordered ASGI send-message types. The OpenAPI case also selects five pointers: the POST operation, operation ID, parameters, request schema, and 201 response schema. The materialized index links this workflow to 11 partial source mappings: `tests/test_application.py`, `tests/test_param_in_path_and_dependency.py`, `tests/test_query.py`, two body tutorial tests, and six tutorial pages. The index marks these mappings partial and says unlisted branches/configurations are not claimed. It is not a parity result: the manifest and atlas say expected outputs are absent and fresh results belong in ignored `parity-results/`.

This workflow has no `APIRouter` registration. It does not exercise a path that matches but has the wrong method, an invalid typed path value, an endpoint returning a raw `Response`, response-model failure, or a custom response class. Those omissions are specific to this 12-case workflow; other reviewed workflows already cover some adjacent behavior, so check their source mapping before adding duplicate cases.

One concrete source/target signature gap is visible in `include_router`: FastAPI accepts `responses`, `default_response_class`, `callbacks`, and `generate_unique_id_function` in addition to prefix/tags/dependencies/schema policy (`applications.py:1441-1614`; router counterpart `routing.py:3133-3244`). ## Prioritized closure plan

1. **Close manifest scope and owner links before making broader claims.** Add reviewed class-level scope for `FastAPI` and `APIRouter` that points to their already reviewed constructor, route, include, and delegated Starlette slices. Keep `add_api_route` private/internal and `api_route` uncertain unless new public-contract evidence changes those classifications. Add an explicit owner mapping for the `APIRoute.get_route_handler` behavior implemented in `FastApiCall`, and record which public options are intentionally outside the supported slice.
2. **Resolve the include/constructor signature gaps.** Add identity-checked `python.signature` probes for `FastAPI.include_router`, `APIRouter.include_router`, and `APIRouter` construction; `python.signature` is supported. Add input-only cases only for source-supported options absent from already reviewed recipes: at minimum include-level `default_response_class`/`responses` propagation and custom route-class or initial-route behavior if that surface is retained. Observe full HTTP status/ordered headers/body and focused OpenAPI pointers; use construction outcome/error selectors for rejected configurations. Do not infer a full signature from the current partial binding.
3. **Reuse existing focused workflows for response, request, and router behavior.** The repository already has `default-response-class-router-upstream`, `response-validation-error-focused`, `request-body-media-type-upstream-v3`, `request-validation-error-details-wave`, `router-body-fields-composition-upstream`, `router-prefix-and-nested-composition-upstream`, and `router-dependencies-isolated`. Map each exact case/selector to its source operation and owner before creating another case. The narrow first-slice residuals worth adding if not already mapped are: (a) a GET to the registered POST-only path (405/Allow, distinct from current path-miss 404); (b) a non-integer `item_id` (path validation, distinct from valid `41`); and (c) one POST through an included APIRouter that combines a body model and response model. Keep wire selectors exact: `http.status`, `http.headers.ordered`, `http.body.bytes`, `asgi.send.message_types`; add focused OpenAPI pointers for route and schemas.
4. **Close the direct-response branch explicitly.** `FastAPI.__call__` has a partial overlay for returned Starlette `Response` bypassing response-model validation, but its manifest row has no direct input workflow reference. Link an existing exact raw-response workflow if it covers this branch; otherwise add one endpoint returning a response with its own status/header/body alongside a response model. Compare exact wire selectors and selected ASGI send types. The response-validation failure case is already represented by `response-validation-error-focused`; retain its direct exception selectors as partial until their catalog support is fully established.
5. **Keep selector capability honest.** First-slice wire body comparison is already exact and adequate for visible validation responses. If claims need direct route identity, validation exception records, or dependency call order, first implement/verify `route.match` (planned), `validation.error_*` (partial), and `dependency.call_order` (planned) selector support, then add those selectors to input-only recipes. Do not broaden a scope from an input recipe alone; the result gate remains isolated, identity-checked oracle/target execution.

No new active recipe, manifest overlay, implementation, or parity result is proposed by this review. The next evidence should be an updated scope/owner map and a minimal recipe delta after the existing workflows are reconciled.
