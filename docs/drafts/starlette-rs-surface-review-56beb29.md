## Route body-size contract captured at 56beb

Starlette 1.6.0 accepts an application `max_body_size` and wraps the app middleware stack when configured; `Route` and `Mount` also accept per-route limits and wrap their ASGI app (`starlette/applications.py:23–58, 63–83; starlette/routing.py:197–231, 363–386 @4f250d6b814587e20c5365f0a5f0c4d42bcb929f`). The 56beb target manifest declares the application argument, marks native `Route.__init__` unimplemented and the Python-package constructor supported, and marks `RequestBodyLimitMiddleware` unimplemented natively (`tests/fixtures/manifest.yaml:303–453, 5499–5587, 11050–11245 @56beb29876e040b8a59afecdf4750d55432c006d`).

The new input-only fixture declares three Python-package cases: an application default with a six-byte body over a five-byte app limit; a route limit of ten over an app limit of five with an eight-byte body; and a route limit of five under an app limit of ten with a six-byte body (`tests/fixtures/sources/parity/route-body-limits.yaml:5–15, 31–65, 131–143, 155–191, 257–269, 281–317 @56beb29876e040b8a59afecdf4750d55432c006d`). The recipe has input/observation declarations, not expected outputs; these cases were not executed in this review.

The FastAPI boundary is narrower and route-origin-sensitive:

- `FastAPI.__init__(**extra)` stores extra keywords in `self.extra`; its docs say these values are not used by FastAPI. Its constructor does not forward `max_body_size` to Starlette’s initializer. FastAPI also overrides `build_middleware_stack` and assembles its own server-error, user, exception, and exit-stack middleware chain (`fastapi/applications.py:863–892, 984–1018, 1020–1068 @95f8322ee1dcda7ceace7b1c4f6c9915b36d748f`). Therefore `FastAPI(max_body_size=...)` is accepted as an extra but is not the Starlette app-level body cap.
- FastAPI’s `APIRoute.__init__` signature has no `max_body_size`; it builds its own request handler instead of initializing the Starlette `Route` wrapper (`fastapi/routing.py:1126–1224 @95f8322ee1dcda7ceace7b1c4f6c9915b36d748f`). FastAPI path operations therefore do not expose this per-route option.
- The deprecated but supported `FastAPI(routes=...)` parameter accepts `BaseRoute` objects and passes them into `APIRouter` (`fastapi/applications.py:73–94, 984–999; fastapi/routing.py:2532–2537 @95f8322ee1dcda7ceace7b1c4f6c9915b36d748f`). A raw Starlette-RS `Route` or `Mount` supplied directly can therefore carry its own wrapper as a compatibility edge; this is distinct from a FastAPI-level default.
- Inclusion changes that edge. FastAPI’s `_IncludedRouter` reconstructs a generic `routing.Route` with path, endpoint, methods, name, and `include_in_schema`, but does not pass `max_body_size`, the original `app`, or middleware. The projected route is then dispatched. The `Mount` branch instead shallow-copies the original mount and changes its path fields, preserving the existing `app` wrapper (`fastapi/routing.py:1653–1677, 1700–1711, 1751–1755, 1782–1802 @95f8322ee1dcda7ceace7b1c4f6c9915b36d748f`). This is a source-path distinction; no live parity was run.
- FastAPI can also accept user-added middleware, but Starlette-RS’s manifest leaves the native `RequestBodyLimitMiddleware` boundary unimplemented. That optional middleware composition is not evidence that FastAPI’s own constructor or `APIRoute` applies the limit.

For FastAPI-RS, classify body limits as no FastAPI app/operation option in the pinned release, with a narrow raw-`BaseRoute` compatibility edge. If the Rust-native FastAPI lane accepts raw Starlette route objects, preserve or explicitly mark the direct `Route`/`Mount` behavior and the included-generic-`Route` projection semantics; the target currently has no native `Route` compatibility constructor or declared native body-limit middleware. The 56beb recipe covers the Python-package `Route` lane only, not FastAPI integration or `Mount` body limits.
